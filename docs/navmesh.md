# タイル型 Navmesh（開発中）

## 生成と結果

`demo/navmesh` の `CreateNavmesh` はモデル、フィールドのワールド変換、
`NavmeshSettings` を受け取り、結果を `Navmesh` オブジェクトとして返します。
内部の `demo/navmesh/terrain` でステージモデルの地形を準備し、描画モデルと同じ FBX
データと変換を使います。フィールドの変換が変わった場合は元メッシュから更新し、
設定・変換に失敗した場合は以前の結果を保持します。

```cpp
auto settings = demo::navmesh::NavmeshSettings{4, 4};
settings.raster.cellSize = 0.3F;       // XZ セル幅
settings.raster.cellHeight = 0.2F;     // 高さの刻み
settings.raster.maxSlopeDegrees = 45;  // 最大傾斜角
settings.voxel.walkable.agentHeight = 2.0F;
settings.voxel.walkable.maxClimb = 0.5F;
settings.voxel.agentRadius = 0.5F;
// settings.voxel.partitionMethod = demo::navmesh::region::PartitionMethod::Watershed;
// settings.voxel.borderCells = 4;     // 省略時は必要な余白を自動計算
auto navmesh = demo::navmesh::CreateNavmesh(model, worldTransform, settings);
```

現在はタイルごとの歩行面、侵食後の距離場、領域、輪郭とポリゴンを構築し、`VoxelTiles()` から読み取り専用で
参照できます。参照は変換更新または `Navmesh` の破棄まで有効です。

XZ のどちらかの幅がゼロの場合は `Stage()` が `TerrainOnly` を返し、`Grid()` と
`VoxelTiles()` は `nullptr` です。それ以外は `VoxelFieldsReady` を返します。
ポリゴン間の接続情報を構築します。経路探索はまだ実装していません。

設定は幅のない地形でも検証します。各タイルがセルを所有できない場合や格子の上限を
超える場合は構築に失敗します。小さい地形ではセル幅を小さくするかタイル数を
減らしてください。設定の自動補正は行いません。
地形の Y 範囲は各タイルが共有し、影響範囲の検索では XZ 方向の境界余白を指定できます。

## 生成設定と処理時間

### 地形・タイル表示

「デバッグ機能」で「地形・タイル表示」を有効にすると、地形 AABB を黄色、タイル枠を
水色で重ねて表示し、別の「地形分割デバッグ」ウィンドウで表示設定を変更できます。
チェックを外すか、このウィンドウを閉じると、ウィンドウと枠が非表示になります。
X・Z の表示用分割数は個別に変更できます。枠は地形に
隠れないよう最前面に描画します。この分割数は Navmesh 構築設定ではありません。

### Navmesh 生成設定

「デバッグ機能」の「Navmesh 生成設定」では、タイル数、セル幅・高さ、最大傾斜、
エージェントの高さ・最大段差・半径、境界余白と領域分割方式を編集できます。

- **Navmesh を再生成**: 編集値を適用し、現在の地形とワールド変換で再生成します。
  配置済み障害物とその識別子は保持します。失敗時は以前の構築結果と設定を保持し、理由を表示します。
- **現在の設定を読み込む**: 未適用の編集を破棄します。

編集値は「Navmesh を再生成」を押すまで適用されません。

### Navmesh 処理時間

「Navmesh 処理時間」では、全体再生成、地形変換、領域分割方式変更、障害物の追加・
個別削除・全削除について、それぞれ直近の処理時間と成否を表示します。時間は
`steady_clock` による実経過時間で、入力選択・描画・GPU 処理は含みません。

未実行や、分割方式が同じ場合・障害物がない全削除などの無操作は計測しません。
生成設定画面でタイル数や余白の入力を拒否した場合も、再生成処理を呼び出さないため計測しません。
ステージを切り替えると計測結果は新しい Navmesh の未計測状態になります。

## ボクセル化とタイル更新

`demo/navmesh/voxelization` には地形三角形を XZ セルごとの高さ方向の占有区間に変換し、
面の傾斜を判定する処理と、頭上空間・段差を判定して歩行面を接続する処理があります。
必要な高さは高さ方向のセル数に切り上げ、許容段差は切り下げます。斜め方向には、
双方の直交方向を経由できる場合のみ接続します。

`voxelization/tiles` の
`DynamicVoxelTiles` は共通格子の地形を一度ボクセル化し、各タイルが所有するセルと
境界余白から歩行面・距離場・領域・輪郭・ポリゴンを作ります。

箱型障害物の追加・個別削除・全削除時は、
障害物が侵食と接続の参照を含む作業範囲に接するタイルだけを、地形と残存障害物から再構築します。
地形の Y 範囲より上にある障害物も、頭上空間を塞ぐ場合は反映します。更新失敗時は
元の障害物と全タイルを保持します。

### タイル境界と余白

タイルとセルの境界が一致しない場合、セルの中心により所有タイルを決めるため、
セルはタイル外にはみ出すことがあります。管理範囲は表示タイルに接するセルを含めて
余白分広げるため、境界の丸めにより余白より広くなる場合があります。セルを所有しない
タイルが発生する設定は拒否します。

現在の最小余白はキャラクター半径の切り上げセル数に、
隣接接続と平滑化の参照用として各１セルを加えた保守的な値です。自動設定または最小値以上の手動指定が
可能です。侵食後の管理範囲とその隣接面を正しく計算できるよう、作業範囲はさらに半径と接続判定の
余白を含みます。そのため、従来より広い範囲のタイルが障害物更新の対象になる場合があります。
タイルの作業セル数の合計は 800 万を上限とします。

## 距離場と侵食

### 距離場

タイルの距離場は管理範囲内で計算し、タイル端そのものを障害物とは扱いません。
侵食後の距離場 `VoxelTile::distance` は侵食面とその接続を除き、新しい境界から構築します。
侵食前の距離場は地形のデバッグ用に `VoxelTile::terrainDistance` として別に保持します。

四方向に移動できない面を 0 とし、前後の走査で直交 2・斜め 3 の重みを使います。
未到達は最大整数値で表し、最大距離は管理範囲の有限値から求めます。平滑化は
接続された八方向と自身の９値を平均し、距離 0 またはキャラクター半径より内側の
元の距離は維持します。元の距離も別に保持します。距離は格子上の近似値であり、
現在の全体距離場とも仕様が異なります。

### キャラクター半径による侵食

キャラクター半径による侵食は距離場の近似値を使わず、接続のない歩行面の境界線と
セル矩形の最短距離を調べます。セル全体を基準とし、距離が半径以下の面は侵食します。
地形端の短いセルにも実際のセル幅を使い、登れる段差は境界にしません。高さ方向の
キャラクター範囲が接する境界を対象とするため、十分離れた階層は区別されます。
高さの近い別階層や別の床の境界でも保守的に侵食される場合があります。
これはボクセル化された歩行面を基準とする判定であり、
元の地形やキャラクターの実際の衝突判定を保証するものではありません。

結果は `VoxelTile::eroded` に歩行面と同じ添字で保持し、1 が侵食面を表します。
管理範囲と隣接接続用余白を含む `erosionArea` 内の面のみ判定済みで、その範囲外の 0 は
歩行可能を意味しません。元の歩行面・接続は `walkable`、侵食面の接続を除いた結果は
`retained` に保持します。後者を使う場合も `erosionArea` 外は未判定です。
障害物の追加・削除でも影響タイルの侵食を
再計算します。１タイルの境界と候補セルの判定は１億回を上限とし、超える場合は構築に失敗します。

## 領域と輪郭

### 単調分割

`demo/navmesh/region/monotone` は侵食されていない所有面を単調領域に分割します。
X 方向の連続列を行ごとに作り、前の行と一対一につながる場合だけ同じ領域として延長します。
分岐や合流では新しい領域を作るため、穴や複数階層がある場合は複数の領域になります。
結果は `VoxelTile::regions.ids` に歩行面と同じ添字で保持し、0 は侵食面・所有範囲外を表します。

### 流域分割

`demo/navmesh/region/watershed` は侵食後の平滑化距離を使用し、四方向でつながる同じ距離の
平坦部のうち、周囲により高い距離がない場所を始点にします。始点から距離の高い面を優先して
広げ、競合時は面の添字と領域 ID で決定的に割り当てます。未到達の接続成分は有限距離の
最大値ではなく独立した平坦部として扱います。上下の階が坂などでつながっていても、
同一領域に同じ XZ セルの複数階層を含めません。現在は小さな領域の統合を行わず、
タイル所有面だけで分割するため、局所的な距離場やタイル境界により領域が細かくなることがあります。
領域 ID はタイル内でのみ有効です。

### 分割方式の変更

既定は単調分割です。`Navmesh::SetPartitionMethod` で方式を変更すると、距離場などは維持したまま
全タイルの領域、輪郭とポリゴンを再構築し、障害物と識別子も保持します。失敗時は元の設定と結果を保持します。

### 輪郭

`demo/navmesh/contour` は領域の四方向接続をたどり、同じ領域の面につながらない辺を
外周・穴として抽出します。結果は `VoxelTile::contours` に保持します。各辺は
`retained.spans` の面と方向を参照するため、元の高さと接続先を確認できます。
領域が右側に来る順番で辺を並べ、XZ 格子上の符号付き面積が正なら外周、負なら穴、
ゼロなら重なった辺を持つ退化輪郭です。タイル間は別領域のため境界辺を残します。
一点で接する辺、通行できない共通辺、段差を省略しません。
表示する元の輪郭はポリゴンとは別に保持します。

## ポリゴンと接続

`demo/navmesh/polygon` は侵食されていない所有面を同じ領域・同じ高さの連結面に分け、
同じ接続先に沿って一直線に続く部分の不要なセル角を省いた輪郭頂点から三角形に分割します。
曲がり角や接続先の切り替わりを残し、穴、一点接触、通行できない共通辺は境界として
保持します。地形端の短いセルは実際の寸法で三角形の向きを判定します。
三角形や結合済みポリゴンの共有辺のうち、結合後に凸形状かつ６頂点以下を
維持できるものを、地形端の切り詰めを含む実際の辺の長さが長い順に結合します。

`VoxelTile::polygonMesh` は小数を含められる格子頂点、凸多角形、三角形と、各歩行面に面積をもって重なる
すべてのポリゴンの対応を保持します。セル対応は三角形とセルの面積による重なりで判定し、
辺や点だけの接触は含めません。
小数座標はセル内の位置を表し、地形端で短くなったセルでもその幅に合わせて描画します。
貪欲な結合は最小ポリゴン数を保証せず、地形によっては以前の矩形分割より増える場合もあります。
異なる高さは別のポリゴンになるため、傾斜はボクセル高さに沿った階段状の近似です。
輪郭の形を変える簡略化は行いません。

### ポリゴン間の接続

`VoxelTiles()->Links()` は双方向のポリゴン接続を保持します。
各リンクは隣接する凸ポリゴンの組ごとに一つ生成し、`adjacency` から双方が参照できます。
リンクの `portals` は両ポリゴンの辺番号と共通格子上の通行可能な共有区間を保持します。
辺の一部分だけが接続される場合や、一つの辺に複数の接続がある場合もあります。
同じ辺に通行できない区間があるときは、共有区間を分けて保持します。
同一高さの内部辺は三角形分割時の境界制約を保持し、
領域・高さ・タイル境界では双方の歩行面が移動可能な区間だけを接続します。
障害物更新では影響タイルのポリゴンだけを再構築し、リンクは全タイルから再作成します。
リンクの参照やポリゴン添字はタイル更新・領域分割変更後には無効です。

## ボクセルとポリゴンのデバッグ表示

「デバッグ機能」の「地形ボクセル+安全距離確認」を有効にすると、専用ウィンドウが開き、
地形モデルの代わりに占有ボクセルを描画します。占有範囲は地形ポリゴンとの交差に基づき、
地面の下全体を塗りつぶすものではありません。水平幅と高さの設定が異なる場合は直方体です。
専用ウィンドウではボクセル表示、距離場の着色、平滑化前後、安全距離確認を切り替えられます。

- **領域の色分け**: 距離色に代えてタイル内の領域 ID ごとに歩行面を着色します。
  色は限られたパレットから選ぶため、異なる領域が同じ色になることがあります。
- **領域分割方式**: 方式を選択し「分割方式を適用」を押すと、単調分割と流域分割を
  切り替えられます。選択だけでは適用されず、適用後の方式は障害物更新やステージ変更でも維持されます。
- **領域の輪郭**: 外周を黄色、穴と退化輪郭を水色の線で表示します。
  各辺は元の歩行面の高さより少し上に表示し、地形やボクセルに隠れないよう最前面に描画します。
- **Navmesh ポリゴン**: 歩行面を緑色、凸多角形の辺を黄色で地形に重ねます。
  描画位置はボクセル歩行面より少し上で、地形や他階層の手前にある部分だけを表示します。
- **Navmesh ポリゴン接続**: 隣接する凸ポリゴンの中心同士を赤い線で結びます。
  線は接続関係を示すもので、移動経路そのものではありません。

### 距離場の色

距離場は既定では侵食前の地形境界からの距離で、「侵食後の距離場」を有効にすると侵食後の
歩行範囲の境界からの距離に切り替わります。侵食後は除外された面を青灰色にし、
「安全距離確認」が有効なら赤色を優先します。

ボクセルは固定方向の光と環境光で面ごとに陰影を付けます。距離色も面の向きに応じて暗くなります。
距離がある歩行面の最上段を黒（近い）から白（遠い）で表し、未到達は紫、
歩行面以外は青灰色にします。「安全距離確認」がオンの間は、侵食された歩行面の最上段を
距離表示のオン・オフにかかわらず赤色にします。オフでは他の歩行面と同じ色で表示します。

白の基準は、地形のボクセルを初めて表示した時点の
全タイル共通の有限最大値です。障害物の追加・削除では基準を変えないため、距離が
変わらないタイルの色も変わりません。基準を超える距離は白で表示します。
侵食前・侵食後それぞれの元の距離と平滑化後には別々の基準があり、
ステージや地形変換の変更時に求め直します。

表示数の上限は 200 万ボクセルで、
超えた場合や描画に失敗した場合はエラーを表示し、元の地形モデルを表示します。
距離場は管理範囲内の近似値であり、白い場所の安全性を保証しません。

## 障害物の配置と削除

「デバッグ機能」で「デバッグ障害物配置」を有効にすると「デバッグ障害物」が開きます。

- **クリックで配置する** を有効にして地形を左クリックすると、幅 1・高さ 2・奥行き 1 の
  箱を配置します。
- **Shift + 左クリック** では、配置の有効・無効にかかわらず、最も手前の障害物を個別に削除できます。
- **全削除** ボタンですべての障害物を削除できます。

UI に捕捉されたクリックや、地形・障害物に当たらないクリックでは操作しません。
選択には描画用のボクセルではなく
ワールド座標の地形三角形を使い、地形に隠れた障害物は選択しません。
障害物は橙色の箱と黄色の枠で表示し、設定ウィンドウを閉じても残ります。

障害物の追加・削除後は、参照用の作業範囲に接するタイルだけを再構築し、距離場の
表示も更新します。障害物が境界の近くにある場合は隣接タイルも再構築されます。
ステージ切り替え時は障害物を破棄します。地形を変換した場合は障害物のワールド座標と
識別子を維持しますが、障害物が残っている状態で地形の XZ 幅をゼロにする変換は拒否します。
経路探索は未実装です。
